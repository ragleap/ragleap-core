# ragleap-phone, Phase 0: provider interface and audio contract (draft)

Status: draft for discussion (RFC issue #814). No phone code is built; every phone-side item is **planned**. The `ragleap-voice` building blocks it will use (stateful resamplers, a stream gate, a batch-adapter `transcribe_stream`) are on main; they do not mean the phone adapter, call integration or phone streaming path exists.
Evidence tags: [verified] seen in the repo or public documentation; [plan] intention; [unverified] not checked.

## 1. Scope

ragleap-phone connects phone calls to RagLeap. Speech (speech to text, text to speech) stays in ragleap-voice.
This note defines two contracts: the provider adapter (how a call source plugs in) and the audio and event
stream between a call and the speech layer. It does not choose a backend; that is the comparison in section 6.

## 2. Connection modes

1. Any SIP trunk through a self-hosted backend. [plan]
2. The customer's own PBX and lines, on premises, possibly without internet. [plan]
3. No phone network: SIP or web calls between apps. [plan]
4. Twilio stays as one adapter so the current behaviour is kept. [plan]

Software alone cannot join the phone network: a real number needs a carrier or a telecom line. Emergency calling is never supported.

## 3. Provider adapter (small abstract class)

    class Adapter:
        name: str
        capabilities: Capabilities     # transport, codecs, dtmf, barge_in, max_concurrent_calls
        async def run(self, on_call) -> None      # accept calls, call on_call(Call) for each
        async def close(self) -> None

    class Call:
        id: str                        # generated by our side; never taken from the remote party
        direction: "inbound" | "outbound"
        async def audio_in(self) -> AsyncIterator[Frame]
        async def send_audio(self, frame) -> None
        async def clear_playback(self) -> None    # barge-in: drop queued audio at once
        async def hangup(self) -> None
        events: AsyncIterator[Event]

Rules for every adapter:
- It authenticates the source of each call before audio is processed, in the way its transport allows.
- It enforces limits: connections, call length, frames per second.
- It never logs audio, transcripts or phone numbers by default.
- It listens on localhost unless the operator opts in.

## 4. Audio and event contract

- Frames: PCM 16-bit little-endian, mono, 20 ms. The phone side is 8 kHz. Mu-law and A-law are converted at the adapter edge.
- The adapter decodes the negotiated codec at its edge. Inbound 8 kHz audio goes to 16 kHz with `Up2Stream` (state kept across frames). Outbound, the adapter reads the sample rate from the synthesis result and must not assume 16 kHz; only a rate that is twice 8 kHz uses `Down2Stream`, any other rate needs an explicitly supported path. `Up2Stream` and `Down2Stream` are merged (PR 1084, exact equality with the one-shot helpers tested); resampling quality and its effect on recognition are not measured. [plan]
- Events: call.started, dtmf (digit), playback.finished (the equivalent of Twilio's mark), call.ended, error.
- Every frame carries a monotonic timestamp so latency can be measured end to end.

### Transport authentication (required)

Status: a requirement for every phone adapter. Implementation is planned; no adapter is assumed to meet it until it is tested. [plan]

Every phone adapter must authenticate its transport before accepting media or acting on provider events.

- Provider webhooks: validate the provider's request signature, or an equivalent authenticated-request mechanism, before processing the webhook.
- Media WebSocket: authenticate the connection with the provider's supported signature or a session token before accepting media frames.
- Where the provider uses separate webhook and media connections, authenticating one must not be treated as authenticating the other. Each connection is authenticated under its own transport contract.

Required behaviour:

1. Unauthenticated media connections are refused by default.
2. Missing, invalid or expired authentication evidence causes the connection or request to be rejected.
3. Authentication is checked before media is accepted or provider events are acted on.
4. A failed check never falls back to an unauthenticated mode.
5. A missing or invalid authentication configuration produces a loud, actionable startup or connection warning. An adapter that cannot enforce authentication must not run as if it were protected.
6. Authentication secrets are never written to logs, transcripts, error messages or diagnostic output.
7. Tests cover accepted and rejected cases for every supported transport.

Acceptance criteria: a correctly authenticated webhook is accepted; a webhook with missing or invalid evidence is rejected; a correctly authenticated media connection is accepted; a media connection without authentication is refused by default; invalid or expired session credentials are rejected; misconfiguration produces a prominent warning and does not silently disable authentication; an authentication failure prevents media processing and event handling.

[unverified] Signature algorithms, token format, credential provisioning, rotation, expiry and revocation depend on the selected provider and transport and must be specified by each adapter design. This requirement does not prescribe a universal mechanism.

## 5. What ragleap-phone needs from ragleap-voice

These are requirements for the Stage 3 streaming design in the 0.1.0 API draft (#762), which reserves the names below:
- `transcribe_stream(chunks, ...)` (package-level, in `ragleap-voice`, PR 1086): a parent-side batch adapter. It buffers the chunks, uses `StreamGate` (PR 1085) to decide whether speech qualified, and runs the batch transcription once at the end. It emits committed segments and a final result, or an explicit no-speech outcome. No partial transcripts from batch engines such as Whisper. Does not need the planned worker streaming protocol.
- `synthesize_stream(text)`: [plan, not built] labelled chunks of a completed synthesis waveform, not model-generated incremental audio. Cancellation stops delivery and discards late output; it cannot interrupt a model call already running, and a worker may have to be killed.
- Measure time to first committed segment, time to final transcript and time to first playable chunk, and record sample rates, codec, buffering and whether the engine is a batch adapter. No partial-result or incremental-generation latency is reported for an implementation that buffers the whole input or waveform first.
- No silent fallback to a hosted service. A phone deployment may run with no internet.
- Targets are measured on real phone audio and published. No number is promised here.

## 7. Out of scope here

Recording, voice cloning on calls (consent store, issue #763), country telephony rules (country champions), emergency calling.
