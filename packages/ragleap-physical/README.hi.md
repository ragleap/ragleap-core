# ragleap-physical

**स्थिति: प्री-अल्फा। केवल सिमुलेशन। यहाँ कुछ भी वास्तविक हार्डवेयर को नियंत्रित नहीं करता।**

एक छोटी लाइब्रेरी जो RagLeap के AI कर्मचारियों को ओपन-सोर्स सिमुलेटरों से जोड़ती है, ताकि लोग सुरक्षित रूप से निर्माण और परीक्षण कर सकें। पहले अवलोकन आता है। हर कार्रवाई एक प्रस्ताव, एक अनुमोदन और एक सुरक्षा-सीमा (safety envelope) से होकर गुज़रती है, जो ब्रिज में, एक ही जगह पर रहती है। मॉडल सीमाओं को नहीं बदल सकता।

## आज क्या काम करता है (और क्या नहीं)

- अवलोकन और प्रस्ताव के प्रारूप (v0), चार क्षमता-स्तर, सुरक्षा-सीमा, ठीक उसी प्रस्ताव से बंधे अनुमोदन, ड्राई रन, परिणाम की जाँच, और एक स्टॉप जिसके लिए अनुमोदन की ज़रूरत नहीं पड़ती। एक छोटे अंतर्निहित एक-जोड़ वाले सिमुलेटर (केवल स्टैंडर्ड लाइब्रेरी) के साथ परखा गया।
- AI एजेंट के लिए ठीक चार टूल: स्रोतों की सूची देखना, एक अवलोकन प्राप्त करना, सुरक्षा-सीमा (envelope) प्राप्त करना, और एक कार्रवाई का प्रस्ताव देना। इनमें से कोई भी न अनुमोदन दे सकता है, न लागू कर सकता है, न स्टॉप कर सकता है, न किसी सीमा को बदल सकता है। इन्हें एक छोटा MCP सर्वर (स्टैंडर्ड लाइब्रेरी, डिफ़ॉल्ट रूप से loopback, वैकल्पिक bearer token) उपलब्ध कराता है। आधिकारिक MCP Python SDK (`mcp>=1.28,<2`) के साथ परखा गया। RagLeap के अपने MCP क्लाइंट को न पढ़ा गया है, न परखा गया है: उसमें बदलाव की ज़रूरत पड़ सकती है (उदाहरण के लिए HTTPS)।
- MuJoCo एडेप्टर वैकल्पिक extra के रूप में: एक केवल-अवलोकन वाला, और एक सर्वो एडेप्टर जो सिमुलेशन में `set_position_target` का पालन करता है, केवल ब्रिज के ज़रिए।
- कार्यक्षेत्र-सीमाएँ: x, y, z में एक बॉक्स, जिसके भीतर हर ट्रैक किया गया बिंदु रहना चाहिए। इसकी जाँच शुरुआती अवस्था पर, ड्राई रन पर, और फिर वास्तविक गति पर छोटे टुकड़ों में होती है। यदि कार्यक्षेत्र तय है और एडेप्टर स्थितियाँ नहीं बता सकता, तो सब कुछ अस्वीकार कर दिया जाता है। दो-कड़ी वाला आर्म मॉडल (अंतर्निहित स्टैंड-इन और MuJoCo) इसे आज़माता है।
- एक सिमुलेटेड मशीन टूल (टूल का घिसाव): AI केवल टूल ऑफ़सेट को, माइक्रोमीटर में, एक सीमा (envelope) के भीतर बदल सकता है (दायरा, चरण का आकार, दो बदलावों के बीच न्यूनतम अंतर)। टूल बदलना एक मानवीय कार्य है, कमांड नहीं। यह गढ़ी हुई संख्याओं वाला एक मॉडल है और किसी वास्तविक मशीन के बारे में कुछ नहीं कहता।
- स्वतंत्र समीक्षा के बाद मज़बूत किया गया (CHANGELOG देखें): कड़ी इनपुट और पूर्वानुमान जाँचें, कोई स्व-अनुमोदन नहीं।
- तीन-जोड़ वाला आर्म मॉडल (`examples/robots/` में MuJoCo XML, साथ में एक अंतर्निहित स्टैंड-इन), एक ऑफ़लाइन ROS 2 केवल-अवलोकन मॉक जिसके लिए ROS इंस्टॉल की ज़रूरत नहीं, और `benchmarks/` में एक दोहराव-क्षमता (repeatability) प्रयोग (एक ही इंस्टॉल किए गए परिवेश में हू-ब-हू पुनःचलन; अलग-अलग मशीनों के बीच दोहराव का दावा नहीं किया जाता)।
- एक ऑपरेटर कंसोल (`ragleap_physical.console`): ब्रिज का मानवीय पक्ष। एक नामित व्यक्ति लंबित प्रस्ताव देखता है, ठीक उसी digest को अनुमोदित करता है, लागू करता है, और स्टॉप कर सकता है। केवल loopback, प्रति व्यक्ति एक token, और अनुमोदन करने वाले का नाम token से आता है, अनुरोध से कभी नहीं। यह कोई टूल नहीं है: AI इस तक पहुँच नहीं सकता।
- दो केवल-अवलोकन औद्योगिक मॉक, जिनमें न नेटवर्क है और न कोई वास्तविक मीटर या मशीन: एक सिमुलेटेड ऊर्जा-स्थल (energy site) और कड़ी सीमाओं वाला एक MTConnect दस्तावेज़-पाठक (यह DTD और entities को अस्वीकार करता है, और आकार की सीमा लगाता है)। ये एडेप्टर केवल-अवलोकन हैं: ये केवल वही दस्तावेज़ पढ़ते हैं जो आप इन्हें देते हैं और कुछ भेजते नहीं। देखें `docs/industry/observe-only-adapters.md` और पहले घंटे की गाइड `docs/first-hour.md`।
- नहीं बना है: दूसरा सिमुलेटर, वास्तविक हार्डवेयर, Java और npm क्लाइंट।
- सिमुलेशन वास्तविकता नहीं है। किसी सफल सिमुलेशन परीक्षण को वास्तविक मशीन के लिए प्रमाण न समझें।

## आज़माएँ

```
pip install -e ".[test]"          # core only, standard library
pip install -e ".[mujoco,test]"   # with the optional MuJoCo adapter
pip install -e ".[test,interop]"  # also runs the MCP SDK interop test
pytest
python examples/demo_fake.py
python examples/two_link_workspace_demo.py
```

कमज़ोरियों की सूचना रिपॉज़िटरी के Security टैब के ज़रिए निजी तौर पर दें (`SECURITY.md` देखें)।
