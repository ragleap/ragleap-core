# Changelog

All notable changes to `ragleap-voice` are documented here. Format loosely
follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]
### Changed
- Hindi number normalization is now version `1+numbers-hi.2`. The parser recognizes the source-attested cardinal spelling `पांच` alongside CLDR's `पाँच`, and protects mixed cardinal/ordinal phrases (including irregular gender/case forms and regular ordinal suffix forms) from partial conversion. Hindi grouping accepts a terminal sentence comma or period only when the complete number is valid; malformed grouping remains uncombined. Unicode NFKC already maps decomposed nukta spellings such as `करोड़` to the lookup spelling `करोड़`. References: [CLDR Hindi RBNF](https://raw.githubusercontent.com/unicode-org/cldr/main/common/rbnf/hi.xml), [Hindi ordinal numerals grammar](https://tplsites.s3.amazonaws.com/resources/HINin-ENGus/grammar/Ordinal_Numerals.htm), and [Omniglot Hindi number table](https://www.omniglot.com/language/numbers/hindi.htm).

## [0.2.0] - 2026-10-30
### Status
- Still pre-alpha. Every model is `unverified` and none is a default. The opt-in number-word normalizers came from an outside contributor, cite CLDR and language references, and have not been reviewed by fluent speakers; they change no benchmark result unless enabled. The energy gate is off by default: at its default floor it passed only 14 of 30 English clips, and Whisper wrote filler text on every silent or noisy clip (see `benchmarks/voice/README.md`). The test suite was also run on Python 3.13 by a team member (370 passed); the package classifiers are unchanged.
### Added
- `ragleap_voice.bench`: opt-in Malay (`numbers="ms"`) cardinal normalization, versioned as `1+numbers-ms.1`, for standalone standard forms from `kosong`/`sifar` through 999,999,999,999,999,999 (below 10^18). CLDR Malay RBNF supplies `belas`, `puluh`, `ratus`, implicit `seribu`/`sejuta`, and the `ribu`, `juta`, `bilion`, `trilion`, and `kuadrilion` scales. Scale groups must descend; malformed, repeated, zero-coefficient, and out-of-range phrases are kept intact. Explicit `satu ribu` is accepted per DBP's formal usage advice. DBP references also verify comma thousands grouping, decimal points, zero (`sifar`), and the value of `kuadrilion`. DBP dictionary entries record both long- and short-scale definitions of `bilion`/`trilion`; this implementation follows current CLDR Malay spellout, DBP school-mathematics definitions (`bilion`=10^9; `trilion`=10^12), and DBP's short-scale numeric example. Complete comma-grouped numeric tokens are normalized, while periods between digits are retained as decimal points. Adjacent single-word cardinals remain separate; number+fraction, ordinal, date, negative, and currency constructions are protected from partial conversion. Ordinals, fractions, dates, negative cardinals, currency, spoken decimals, dialect/inflected variants, and values at or above 10^18 are outside scope. Common cardinal homonyms such as `satu` in prose can still normalize; no fluent Malay speaker reviewed this implementation. References: [Unicode CLDR Malay cardinal RBNF](https://github.com/unicode-org/cldr/blob/main/common/rbnf/ms.xml), [CLDR number-formatting specification](https://unicode.org/reports/tr35/tr35-numbers.html), [DBP Pedoman Umum Ejaan Bahasa Melayu](https://eseminar.dbp.gov.my/dokumen/ejaan.pdf), [DBP PRPM mathematical glossary entries for bilion/trilion](https://prpm.dbp.gov.my/Cari1?d=7120&keyword=ini), [DBP PRPM definition of sifar](https://prpm.dbp.gov.my/Cari1?d=7120&keyword=sifar), and [DBP PRPM definitions and short-scale clarification for bilion](https://prpm.dbp.gov.my/Cari1?d=73980&keyword=bilion).
- `ragleap_voice.bench`: opt-in Hindi (`numbers="hi"`) cardinal normalization, versioned as `1+numbers-hi.1`, for Devanagari spellings from zero through 99 खरब (9,999,999,999,999). The lexical table follows Unicode CLDR's Hindi cardinal RBNF, accepting spelling variants attested in BIS or the grammar reference, including छै, ब्यालीस, उन्यासी, इक्यानवे, and पचानवे; composition uses descending सौ, हज़ार/हजार, लाख, करोड़, अरब, and खरब scales. Repeated, increasing, zero-coefficient, and out-of-range scale phrases remain unchanged; Hindi conjunction और and source-documented fraction markers keep unsupported phrases intact. Ordinals, fractions, negatives, spoken decimals, dates, currency, collective/aggregate forms, transliterations, and values using larger scales are excluded. The parser is context-free, so common number words such as एक in ordinary prose may still normalize. Hindi numeric punctuation uses Indian comma grouping and a decimal point; only complete valid grouped numbers are de-grouped. References: [CLDR Hindi cardinal RBNF](https://raw.githubusercontent.com/unicode-org/cldr/main/common/rbnf/hi.xml), [CLDR Hindi locale number patterns](https://raw.githubusercontent.com/unicode-org/cldr/main/common/main/hi.xml), [BIS IS 16500:2012, Devnagari Script and Hindi Spellings](https://www.bis.gov.in/wp-content/uploads/2025/03/ISH16500_2012.pdf), [Central Hindi Training Institute Hindi coursebook](https://chti.rajbhasha.gov.in/pdf/Prabodh_Paathmaala.pdf), and [Hindi Cardinal Numerals grammar reference](https://tplsites.s3.amazonaws.com/resources/HINin-ENGus/grammar/Cardinal_Numerals.htm), plus its [Fractional Numerals reference](https://tplsites.s3.amazonaws.com/resources/HINin-ENGus/grammar/Fractional_Numerals.htm). CLDR, BIS, and the Hindi grammar reference differ on some number spellings; only alternatives directly attested in these sources are accepted.
- `ragleap_voice.bench`: opt-in Brazilian Portuguese (`numbers="pt-BR"`) cardinal normalization, versioned as `1+numbers-pt-BR.1`, supporting standard forms from zero through 999,999,999,999,999,999 and Brazilian short-scale names through `quadrilhão`, including the dictionary-verified variant `quatrilhão` (plural `quatrilhões`). CLDR's Portuguese RBNF supplies cardinal spellings, agreement variants and the scale sequence; the Brazilian Portuguese locale file has no number-rule overrides. Composition, thousands periods and decimal commas were cross-checked against the Câmara Municipal de Belo Horizonte's number-writing guide and FUNAG's Manual de Revisão. The Academia Brasileira de Letras lists both `quatorze` and `catorze`; both map to 14. Malformed scale phrases are preserved, adjacent standalone cardinals remain separate, and common fraction/ordinal markers prevent partial numerator conversion. Ordinals, fractions, spoken decimals, dates, currency-specific handling, dialect forms, negatives, and values at or above 10^18 are excluded. Agreement and number-versus-prose use are context-sensitive, so common cardinals in ordinary text may still normalize. Complete period-grouped numbers are normalized only when the entire number-like token is valid; decimal commas are retained and malformed period/comma sequences are not partially combined. No external word list or runtime dependency is added. References: [CLDR Portuguese RBNF](https://raw.githubusercontent.com/unicode-org/cldr/main/common/rbnf/pt.xml), [CLDR pt_BR locale data](https://raw.githubusercontent.com/unicode-org/cldr/main/common/main/pt_BR.xml), [CLDR Portuguese number-format chart](https://www.unicode.org/cldr/charts/47/verify/numbers/pt.html), [Câmara Municipal de Belo Horizonte number guide](https://cmbhweb.cmbh.mg.gov.br/atividade-legislativa/guia-de-reda%C3%A7%C3%A3o/algarismo-ou-extenso), [FUNAG Manual de Revisão, “Números”](https://funag.gov.br/manual/index.php?title=N%C3%BAmeros), and [Academia Brasileira de Letras Formulário Ortográfico](https://www.academia.org.br/nossa-lingua/formulario-ortografico), the [Michaelis](https://michaelis.uol.com.br/palavra/e3Qd8/quatrilh%C3%A3o/) and [Aulete](https://www.aulete.com.br/quatrilh%C3%A3o) dictionary entries for `quatrilhão`, and a [USP linguistics paper on Portuguese fractions](https://aclanthology.org/2021.stil-1.37.pdf).
- `ragleap_voice.bench`: opt-in Indonesian (`numbers="id"`) cardinal normalization, versioned as `1+numbers-id.1`, for standard standalone forms from zero through 999 triliun. Composition and scale names were checked against [Unicode CLDR's Indonesian RBNF data](https://github.com/unicode-org/cldr/blob/main/common/rbnf/id.xml), [Tata Bahasa Baku Bahasa Indonesia](https://repositori.kemendikdasmen.go.id/16351/1/Tata%20Bahasa%20Baku%20Bahasa%20Ind.pdf), and Sneddon's [Indonesian Reference Grammar](https://theswissbay.ch/pdf/Books/Linguistics/Mega%20linguistics%20pack/Austronesian/Indonesian%20Reference%20Grammar%20%28Sneddon%29.pdf). CLDR's [Indonesian locale data](https://github.com/unicode-org/cldr/blob/main/common/main/id.xml) defines periods for grouping and commas for decimals. An older official [2000 terminology guide](https://repositori.kemendikdasmen.go.id/1676/1/Pedoman%20Umum%20Pembentukan%20Istilah%20%282000%29.pdf) assigns `biliun` differently, so that ambiguous scale and forms above `triliun` are excluded; the current CLDR rules and Tata Bahasa Baku agree on `miliar` (10^9) and `triliun` (10^12). Malformed scale sequences are preserved and adjacent standalone cardinals remain separate, including when joined by `dan`. Fraction markers are recognized compositionally as `per-` or `seper-` plus a supported single-word cardinal denominator, keeping the complete phrase outside cardinal conversion; EYD V documents the `per-` denominator convention and examples including `tiga perempat`, `dua persepuluh`, and `seperenam belas`. Ordinals, fractions, dates, currency, digit-by-digit `kosong`, and regional or older spellings are excluded; context-free matches such as ordinary-prose `satu` remain possible. Indonesian grouped numbers validate the full number-like token, including the comma-decimal portion, before removing periods; Italian period handling remains separately versioned as `numbers-it.2`. Defaults and other language modes are unchanged; no external word list is bundled at runtime.
- `ragleap_voice.bench`: opt-in Italian (`numbers="it"`) cardinal normalization, versioned as `1+numbers-it.2` to distinguish the corrected behavior from the original `1+numbers-it.1` release. Supports standard forms from zero through `999,999,999,999,999,999`, including closed compounds through 999,999 and long-scale nouns through `biliardo` (10^15). Spellings and composition were checked against [Unicode CLDR's Italian RBNF data](https://raw.githubusercontent.com/unicode-org/cldr/main/common/rbnf/it.xml), CLDR's [Italian decimal and grouping symbols](https://raw.githubusercontent.com/unicode-org/cldr/main/common/main/it.xml), Treccani's [cardinal numeral guidance](https://www.treccani.it/enciclopedia/numerali-prontuario_%28Enciclopedia-dell%27Italiano%29/), [Accademia della Crusca's spelling guidance](https://accademiadellacrusca.it/it/consulenza/quarantaquattro-gatti-in-fila-per-sei-col-resto-di-due-o-di-quando-e-come-scrivere-i-numeri-in-lettere/1077), and the University of Messina's [DICO guidance on numeral forms](https://dico.unime.it/ufaq/la-forma-dei-numerali-cardinali-e-ordinali/) and [number composition](https://dico.unime.it/ufaq/numeri-e-parole/). Treccani confirms `bilione` as 10^12 and [biliardo](https://www.treccani.it/enciclopedia/biliardo_%28Enciclopedia-della-Matematica%29/) as 10^15; the Crusca source describes Italy's long scale. `trilione` and larger scales, ordinals, dates, currency, and nonstandard/dialect forms are excluded; adjacent standalone numbers remain separate, decimal commas are retained, and complete period groups are normalized as thousands separators. Defaults and other language modes are unchanged; no external word list is bundled at runtime.
- `ragleap_voice.bench`: opt-in German (`numbers="de"`) cardinal-number normalization, versioned as `1+numbers-de.1`. Standard standalone forms through Billiarde (10^15), compounds below one million, and German long-scale groupings are checked against [CLDR's German RBNF rules](https://github.com/unicode-org/cldr/blob/main/common/rbnf/de.xml) and Duden's [large-number spelling guidance](https://www.duden.de/sprachwissen/sprachratgeber/Schreibung-von-Zahlen). Malformed scale sequences are preserved. Defaults and other language paths are unchanged; no external word list is bundled at runtime.
- `ragleap_voice.bench`: opt-in Spanish (`numbers="es"`) cardinal-number normalization, versioned as `1+numbers-es.1`. Standalone cardinal forms and combinations are checked against the RAE's [cardinal-numeral reference](https://www.rae.es/diccionario-estudiante/docs/numerales.pdf), definitions of [millardo](https://dle.rae.es/millardo), [billón](https://dle.rae.es/bill%C3%B3n), [trillón](https://dle.rae.es/trill%C3%B3n) and [cuatrillón](https://dle.rae.es/cuatrill%C3%B3n), and CLDR's [Spanish RBNF data](https://github.com/unicode-org/cldr/blob/main/common/rbnf/es.xml). The general Spanish long scale is supported; the US short-scale variant is outside scope. Repeated or increasing scale sequences are preserved, adjacent standalone numerals are normalized separately, and Spanish decimal commas are not removed as thousands separators. Defaults and the English and Turkish paths are unchanged; no external word list is bundled at runtime.
- `transcribe()` adds a note when the whole output equals a filler phrase Whisper wrote for silence and noise in the gate benchmark ("thank you", "thanks for watching", "you"), or when the output is empty. A note only: the text is never changed. The list is short, English only and not a general detector of invented text.
- Energy gate for `transcribe()` (`gate="off"` by default, or `"energy"`, with `gate_options`): when no 20 ms frame is speech-like the engine is not run and the result is empty text with a note giving the levels. Standard library only. The thresholds (floor -46.8 dBFS from the older voice channel, 30 dB relative, 5 frames) are unmeasured starting points, a level gate cannot tell loud noise from speech, and no protection against invented text is claimed until a benchmark exists.
- Audio helpers without `audioop` (`ragleap_voice.audio`, standard library only, not exported yet): mu-law decode and encode, 20 ms framing, RMS and peak in dBFS, gain and level normalisation, 2:1 resamplers. The mu-law encoder is not verified against the G.711 standard (it differs from audioop and from ffmpeg by one code on 0.6% and 1.3% of inputs); A-law is not implemented; the resamplers' effect on recognition accuracy is not measured.
- `ragleap_voice.bench`: opt-in Turkish ordinal normalization for standalone and composed number words, plus standard digit-plus-ordinal-suffix spellings. Supports both `katrilyoncu` and `katrilyonuncu`. The Turkish normalizer version is now `1+numbers-tr.2`; defaults and the English path are unchanged. TDK's [number spelling guidance](https://tdk.gov.tr/icerik/yazim-kurallari/sayilarin-yazilisi/) covers ordinal writing conventions and digit suffixes; lexical examples are authored for the tests and cross-checked against Turkish references.

## [0.1.0] - 2026-10-26
### Status
- First release with speech engines. Pre-alpha: every model is `unverified`, none is a default, and calls need `allow_unverified=True`. The core still has no runtime dependencies.
- Some entries below were written before the real-model runs and say "tested with fakes only" or "CUDA not run". Since then (reported in issues #960 and #970): the Whisper engine ran with the real model on two clips (en, es) on a CPU, and on one Colab T4 with `nvidia-cublas-cu12` and `nvidia-cudnn-cu12` preloaded by hand; the Parler engine ran on a T4 for Hindi and English. These are a few clips on one machine, not accuracy or quality measurements.
### Added
- Whisper `device="cuda"` ran on two clips (en, es) on one Colab T4 after installing `nvidia-cublas-cu12` and `nvidia-cudnn-cu12` and preloading them with `ctypes`. The CUDA error hint and the README now say so; the engine still does not preload libraries itself.
- Indic Parler-TTS engine (`parler`), the first text-to-speech engine, as an isolated worker (`parler_engine.py`, `parler_worker.py`). The user sets up the Python environment (torch, transformers, parler-tts) and names it in `RAGLEAP_VOICE_PARLER_PYTHON`. The worker reads only the verified model folders and takes the description tokenizer from the locked flan-t5 tokenizer folder. Languages hi, ta, te, ml, kn, en; no named emotion controls (style goes through `options={"description": ...}`); `speed` and `emotion` are refused. Tested with fakes only: not run with the real model, and the model is gated on Hugging Face and still `unverified`.
- Isolated-worker framework (`ragleap_voice.worker`, `worker_runtime.py`), standard library only: a `WorkerEngine` runs in a separate Python process from an environment the user sets up (`RAGLEAP_VOICE_WORKER_PYTHON`), speaks JSON lines (`load`, `run`, `close`), starts with an allowlisted environment (no tokens, offline variables, private home and Hugging Face folders), passes audio as files in a private folder, writes the worker's stderr to a log file named in `EngineError`, and applies a timeout per call. It is not a security sandbox. Tested with a fake worker script only: no real engine uses it yet.
- `synthesize(text, language=, engine=, emotion=, speed=, allow_unverified=, cache_dir=, options=)`: text to speech with the same model checks as `transcribe()`. The `voice` parameter is reserved and raises `UnsupportedFeatureError` (cloning needs the consent store, issue #763). Emotion needs an engine that declares it and says in `notes` when the language is outside the authors' support. Every result is marked synthetic; `watermarked` follows the engine. Tested with fake engines only: no speech-synthesis engine exists yet.
- Whisper engine fix after the first real-model run on Colab: it now decodes the WAV itself and passes float32 samples to faster-whisper (the BytesIO path failed with `metadata_errors` when PyAV 19 was installed), accepts only mono 16-bit 16 kHz WAV, has a `device` option (`auto`, `cpu`, `cuda`) and turns a missing CUDA library into `EngineUnavailableError`. The CPU path ran with the real model on two clips; the CUDA path has not run yet.
- Whisper large-v3 engine (`whisper`) on faster-whisper, behind the optional extra `ragleap-voice[whisper]` (faster-whisper 1.2.1). It loads only a verified local folder with local files only, declares the nine languages with a usable measured result, has no voice-activity gate and says so in every result. Tested with a fake `WhisperModel` only: not run with the real model yet, and the model entry is still `unverified`.
- `transcribe(audio, language=, engine=, allow_unverified=, cache_dir=, timestamps=, options=)`: reads a PCM WAV (path or bytes) with the standard `wave` module, picks an engine (`auto` never chooses a third-party engine), checks the licence, the verification status and the lock of every model the engine needs, and hands the engine verified directories only. Errors are never turned into defaults. `Capabilities` gains `detects_language`. Tested with fake engines only: no speech engine or model is part of it yet.
- First code toward 0.1.0, standard library only and with no speech engines: the exception hierarchy, frozen result types (`Transcript`, `Segment`, `Speech`), the engine interface (`Capabilities`, `Request`, `Result`, `EngineInfo`) and a registry in which third-party engines are never chosen by automatic selection. `transcribe()` and `synthesize()` are not part of it yet. See `docs/design/api.md`.
- Lock files for `naijavox-2` and `sunflowerasr-51-african-languages` and their digests in `models.toml`. Both entries stay `unverified`; the training-data licences of both models have not been reviewed. NaijaVox's sample audio and images are not part of its lock.
- Manifest entries `naijavox-2` and `sunflowerasr-51-african-languages` (unverified candidates, no lock yet, not in the default path) and a notice listing their training datasets with licences not reviewed. The matching rows in `coverage/stt.csv` now use these names instead of the `candidate:` prefix.

## [0.0.2] - 2026-10-19
### Changed
- Still the model-management layer only: there are no speech engines in this release.
- Project URLs point at the ragleap organisation (the repository moved to ragleap/ragleap-core).
- The `whisper-large-v3` manifest entry now names the repository we run (`Systran/faster-whisper-large-v3`) at a pinned revision; it named `openai/whisper-large-v3` with no revision. It stays unverified.
### Added
- Language coverage matrix as data: `coverage/stt.csv` and `coverage/tts.csv` (one row per language and engine, with tier, interval, test set and evidence), a standard-library checker `ragleap_voice.coverage`, tests, and packaging of the files in the wheel. Rows come only from measurements already in `benchmarks/voice/README.md`; unmeasured languages are tier 1 rows that say so. No raw per-clip results are committed yet.
- Benchmark JSON result metadata now records the normalizer version used for the run. Files from before this field was added are version "1".
- `ragleap_voice.bench`: optional number normalization for WER/CER and `run_stt`. `numbers=True` (or `"en"`) retains English behavior; `numbers="tr"` adds Turkish cardinal-number words. The option stays off by default, so published results are unchanged; unsupported language strings raise ValueError rather than silently falling back to English. `normalizer_version(numbers)` returns `"1"`, `"1+numbers-en.1"`, or `"1+numbers-tr.1"` for the selected configuration. Both modes map decimal digits of any script to ASCII. Turkish coverage is standalone cardinal numbers through katrilyon; ordinals, dates, currency-specific handling, dialect and inflected forms are not covered. Test sentences are author-written; no external number-word data is included.
- Lock files: an optional per-file `format` tag (only `ctranslate2` on `.bin` files) lets a verified entry list CTranslate2 weights without relaxing the pickle rule for any other file. The tag is covered by the lock digest, and `models verify` and `models pull` check the file header as well as size and SHA-256. `models lock` accepts `--format PATH=NAME` to write the tag; it downloads a tagged file to a temporary folder to check its header first.
- Lock file `locks/whisper-large-v3.json` (Systran/faster-whisper-large-v3 at edaa852ec7e1, 7 files, `model.bin` tagged `ctranslate2`) and its digest in `models.toml`. The entry stays `unverified`: no verification criteria for speech-to-text exist yet and no human review has happened.

## [0.0.1] - 2026-10-15
### Added
- First release: the model-management layer only (manifest, lock files, hash-verified downloads, CLI). There are no speech engines in this release.
- Lock file `locks/flan-t5-large-tokenizer.json` (5 tokenizer files, no weights, revision 0613663d0d48) and `depends_on = ["flan-t5-large-tokenizer"]` on `indic-parler-tts`: `models pull indic-parler-tts` now fetches both repositories, tokenizer first. Both entries stay unverified pending human review.
- Manifest entries may declare `depends_on` (a list of other entries). `models pull` fetches dependencies first and checks that every lock exists before downloading anything; `models verify` checks them too; `models check` rejects unknown names, self-dependencies, duplicates and cycles, and a verified or default entry may only depend on verified entries. A verified entry that is not a default is now held to the same rules as a default one (pinned revision, 64-hex lock digest, allowlisted licences).
- Manifest entry `flan-t5-large-tokenizer` (unverified, not locked yet): the tokenizer files of the text encoder that Indic Parler-TTS loads at run time. Apache-2.0 per the model card.
- First lock file: `locks/indic-parler-tts.json` (revision 660bc53c64ae, 10 files, 3.5 GiB, safetensors only), built and pulled end to end against the real gated Hugging Face repository. Pinned in `models.toml` but still `unverified` pending human review; the separate `google/flan-t5-large` repository its config loads at run time is not covered.
- Lock files for verified or default entries may not list pickle-capable files (.pt, .pth, .bin, .pkl, .pickle, .ckpt, .joblib, .dill): `models check` fails them, `models pull` refuses verified entries that do and warns for unverified ones, and `models lock` warns when its plan includes such files.
- Fix: `models pull` now sends the Hugging Face token on redirects that stay on huggingface.co (gated repositories answer with another huggingface.co URL), still never to another host and never again once a redirect has left huggingface.co.
- `ragleap-voice models pull NAME` (Hugging Face only: HTTPS, host allowlist, manual redirect validation, token sent only to huggingface.co (never to a CDN), per-file size and SHA-256 checks in a staging directory, disk-space check, offline mode) and `models lock NAME` (maintainer tool). Tested against a local fake server only.
- Lock files (`locks/<model>.json`: path, size and SHA-256 per file) with strict validation, a cache layout, and `ragleap-voice models verify NAME` (offline). `models check` now requires a matching lock for every verified or default entry. No download command yet.
- Model manifest loader (`ragleap_voice.manifest`), a strict TOML subset reader for Python 3.10 (`ragleap_voice._toml`) and a read-only `ragleap-voice models list|show|check` command line. No download command yet.
- Package scaffold, licence allowlist, `models.toml` manifest schema and CI licence test.
- `ragleap_voice.bench`: WER/CER metrics with a shared normalizer, CSV test manifest with licence checks, STT runner that records raw CSV/JSON results with environment metadata.
