# Changelog

All notable changes to `ragleap-voice` are documented here. Format loosely
follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]
### Added
- Whisper `device="cuda"` ran on two clips (en, es) on one Colab T4 after installing `nvidia-cublas-cu12` and `nvidia-cudnn-cu12` and preloading them with `ctypes`. The CUDA error hint and the README now say so; the engine still does not preload libraries itself.
- Indic Parler-TTS engine (`parler`), the first text-to-speech engine, as an isolated worker (`parler_engine.py`, `parler_worker.py`). The user sets up the Python environment (torch, transformers, parler-tts) and names it in `RAGLEAP_VOICE_PARLER_PYTHON`. The worker reads only the verified model folders and takes the description tokenizer from the locked flan-t5 tokenizer folder. Languages hi, ta, te, ml, kn, en; no named emotion controls (style goes through `options={"description": ...}`); `speed` and `emotion` are refused. Tested with fakes only: not run with the real model, and the model is gated on Hugging Face and still `unverified`.
- Isolated-worker framework (`ragleap_voice.worker`, `worker_runtime.py`), standard library only: a `WorkerEngine` runs in a separate Python process from an environment the user sets up (`RAGLEAP_VOICE_WORKER_PYTHON`), speaks JSON lines (`load`, `run`, `close`), starts with an allowlisted environment (no tokens, offline variables, private home and Hugging Face folders), passes audio as files in a private folder, writes the worker's stderr to a log file named in `EngineError`, and applies a timeout per call. It is not a security sandbox. Tested with a fake worker script only: no real engine uses it yet.
- `synthesize(text, language=, engine=, emotion=, speed=, allow_unverified=, cache_dir=, options=)`: text to speech with the same model checks as `transcribe()`. The `voice` parameter is reserved and raises `UnsupportedFeatureError` (cloning needs the consent store, issue #763). Emotion needs an engine that declares it and says in `notes` when the language is outside the authors' support. Every result is marked synthetic; `watermarked` follows the engine. Tested with fake engines only: no speech-synthesis engine exists yet.
- Whisper engine fix after the first real-model run on Colab: it now decodes the WAV itself and passes float32 samples to faster-whisper (the BytesIO path failed with `metadata_errors` when PyAV 19 was installed), accepts only mono 16-bit 16 kHz WAV, has a `device` option (`auto`, `cpu`, `cuda`) and turns a missing CUDA library into `EngineUnavailableError`. The CPU path ran with the real model on two clips; the CUDA path has not run yet.
- Whisper large-v3 engine (`whisper`) on faster-whisper, behind the optional extra `ragleap-voice[whisper]` (faster-whisper 1.2.1). It loads only a verified local folder with local files only, declares the nine languages with a usable measured result, has no voice-activity gate and says so in every result. Tested with a fake `WhisperModel` only: not run with the real model yet, and the model entry is still `unverified`.
- `transcribe(audio, language=, engine=, allow_unverified=, cache_dir=, timestamps=, options=)`: reads a PCM WAV (path or bytes) with the standard `wave` module, picks an engine (`auto` never chooses a third-party engine), checks the licence, the verification status and the lock of every model the engine needs, and hands the engine verified directories only. Errors are never turned into defaults. `Capabilities` gains `detects_language`. Tested with fake engines only: no speech engine or model is part of it yet.
- First code toward 0.1.0, standard library only and with no speech engines: the exception hierarchy, frozen result types (`Transcript`, `Segment`, `Speech`), the engine interface (`Capabilities`, `Request`, `Result`, `EngineInfo`) and a registry in which third-party engines are never chosen by automatic selection. `transcribe()` and `synthesize()` are not part of it yet. See `docs/design/api.md`.
- Lock files for `naijavox-2` and `sunflowerasr-51-african-languages` and their digests in `models.toml`. Both entries stay `unverified`; the training-data licences of both models have not been reviewed. NaijaVox's sample audio and images are not part of its lock.
- Manifest entries `naijavox-2` and `sunflowerasr-51-african-languages` (unverified candidates, no lock yet, not in the default path) and a notice listing their training datasets with licences not reviewed. The matching rows in `coverage/stt.csv` now use these names instead of the `candidate:` prefix.

## [0.0.2] - 2026-10-19
### Changed
- Still the model-management layer only: there are no speech engines in this release.
- Project URLs point at the ragleap organisation (the repository moved to ragleap/ragleap-core).
- The `whisper-large-v3` manifest entry now names the repository we run (`Systran/faster-whisper-large-v3`) at a pinned revision; it named `openai/whisper-large-v3` with no revision. It stays unverified.
### Added
- Language coverage matrix as data: `coverage/stt.csv` and `coverage/tts.csv` (one row per language and engine, with tier, interval, test set and evidence), a standard-library checker `ragleap_voice.coverage`, tests, and packaging of the files in the wheel. Rows come only from measurements already in `benchmarks/voice/README.md`; unmeasured languages are tier 1 rows that say so. No raw per-clip results are committed yet.
- Benchmark JSON result metadata now records the normalizer version used for the run. Files from before this field was added are version "1".
- `ragleap_voice.bench`: optional number normalization for WER/CER and `run_stt`. `numbers=True` (or `"en"`) retains English behavior; `numbers="tr"` adds Turkish cardinal-number words. The option stays off by default, so published results are unchanged; unsupported language strings raise ValueError rather than silently falling back to English. `normalizer_version(numbers)` returns `"1"`, `"1+numbers-en.1"`, or `"1+numbers-tr.1"` for the selected configuration. Both modes map decimal digits of any script to ASCII. Turkish coverage is standalone cardinal numbers through katrilyon; ordinals, dates, currency-specific handling, dialect and inflected forms are not covered. Test sentences are author-written; no external number-word data is included.
- Lock files: an optional per-file `format` tag (only `ctranslate2` on `.bin` files) lets a verified entry list CTranslate2 weights without relaxing the pickle rule for any other file. The tag is covered by the lock digest, and `models verify` and `models pull` check the file header as well as size and SHA-256. `models lock` accepts `--format PATH=NAME` to write the tag; it downloads a tagged file to a temporary folder to check its header first.
- Lock file `locks/whisper-large-v3.json` (Systran/faster-whisper-large-v3 at edaa852ec7e1, 7 files, `model.bin` tagged `ctranslate2`) and its digest in `models.toml`. The entry stays `unverified`: no verification criteria for speech-to-text exist yet and no human review has happened.

## [0.0.1] - 2026-10-15
### Added
- First release: the model-management layer only (manifest, lock files, hash-verified downloads, CLI). There are no speech engines in this release.
- Lock file `locks/flan-t5-large-tokenizer.json` (5 tokenizer files, no weights, revision 0613663d0d48) and `depends_on = ["flan-t5-large-tokenizer"]` on `indic-parler-tts`: `models pull indic-parler-tts` now fetches both repositories, tokenizer first. Both entries stay unverified pending human review.
- Manifest entries may declare `depends_on` (a list of other entries). `models pull` fetches dependencies first and checks that every lock exists before downloading anything; `models verify` checks them too; `models check` rejects unknown names, self-dependencies, duplicates and cycles, and a verified or default entry may only depend on verified entries. A verified entry that is not a default is now held to the same rules as a default one (pinned revision, 64-hex lock digest, allowlisted licences).
- Manifest entry `flan-t5-large-tokenizer` (unverified, not locked yet): the tokenizer files of the text encoder that Indic Parler-TTS loads at run time. Apache-2.0 per the model card.
- First lock file: `locks/indic-parler-tts.json` (revision 660bc53c64ae, 10 files, 3.5 GiB, safetensors only), built and pulled end to end against the real gated Hugging Face repository. Pinned in `models.toml` but still `unverified` pending human review; the separate `google/flan-t5-large` repository its config loads at run time is not covered.
- Lock files for verified or default entries may not list pickle-capable files (.pt, .pth, .bin, .pkl, .pickle, .ckpt, .joblib, .dill): `models check` fails them, `models pull` refuses verified entries that do and warns for unverified ones, and `models lock` warns when its plan includes such files.
- Fix: `models pull` now sends the Hugging Face token on redirects that stay on huggingface.co (gated repositories answer with another huggingface.co URL), still never to another host and never again once a redirect has left huggingface.co.
- `ragleap-voice models pull NAME` (Hugging Face only: HTTPS, host allowlist, manual redirect validation, token sent only to huggingface.co (never to a CDN), per-file size and SHA-256 checks in a staging directory, disk-space check, offline mode) and `models lock NAME` (maintainer tool). Tested against a local fake server only.
- Lock files (`locks/<model>.json`: path, size and SHA-256 per file) with strict validation, a cache layout, and `ragleap-voice models verify NAME` (offline). `models check` now requires a matching lock for every verified or default entry. No download command yet.
- Model manifest loader (`ragleap_voice.manifest`), a strict TOML subset reader for Python 3.10 (`ragleap_voice._toml`) and a read-only `ragleap-voice models list|show|check` command line. No download command yet.
- Package scaffold, licence allowlist, `models.toml` manifest schema and CI licence test.
- `ragleap_voice.bench`: WER/CER metrics with a shared normalizer, CSV test manifest with licence checks, STT runner that records raw CSV/JSON results with environment metadata.
